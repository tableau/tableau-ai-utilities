# Metric Dictionary Structures

Output templates for Brief and Detailed Metric Dictionary documents.

Formulas, calculation types, parameter values and defaults, and joins or blends are not available through the Tableau MCP. Wherever a template asks for one, write "Not available via MCP; confirm with the owner" (for a calculated field's Type and Inputs, "confirm with data owner") unless the user supplied the formula.

## Brief Metric Dictionary Structure

Target: ~1 page. One-liner definitions for quick lookup.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Metric Dictionary — [Datasource Name] (Summary)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Datasource: [Name] | Owner: [from list-datasources, else Not available via MCP; confirm with the owner]
Fields documented: [count] | Scope: Measures & Calcs

MEASURES
| Metric | Definition | Direction |
|--------|-----------|-----------|
| [Name] | [One-line plain-language definition] | ↑/↓/→ |
| [Name] | [One-line plain-language definition] | ↑/↓/→ |
[One row per measure]

CALCULATED FIELDS
| Field | What It Does | Type |
|-------|-------------|------|
| [Name] | [One-line explanation from name/description] | [confirm with data owner] |
| [Name] | [One-line explanation from name/description] | [confirm with data owner] |
[One row per calc. Brief dictionaries never include a parameters table.]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**Length target:** 30-60 lines. Table-based, scannable.

Target: 3-5 pages. Full field-level documentation.

```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Generated by Tableau Scribe | [Date]
Datasource: [Name] | LUID: [ID]
Owner: [from list-datasources if it returned one, else Not available via MCP; confirm with the owner]
Project: [same rule]

• Business context: [Why someone would look at this]

  Depends on context]
• Aggregation: [SUM / AVG / COUNT / COUNTD / etc.]

• Typical range: [Based on sample query, if available]

• Caveats: [NULL handling, edge cases, known issues]

[Repeat for each primary measure]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CALCULATED FIELDS

• Definition: [What this calculates in plain language]
• Plain-language logic: [How it works, from the name and
  description only; if neither explains it, "confirm with data
  owner". NO formulas unless the user supplied one]
• Type: [confirm with data owner — or Row-level / Aggregate /
  LOD / Table Calc if the user supplied the formula]
• Inputs: [confirm with data owner — or the fields the user's
  formula names]
• Directionality: [Higher/Lower/Context-dependent]
• When to use: [In what analysis context is this relevant]
• Caveats: [Filter sensitivity, NULL behavior, version reqs]

[Repeat for each calculated field]

SECONDARY MEASURES (if present)

KEY DIMENSIONS (if all-fields scope selected)

• Definition: [What this categorizes]
• Cardinality: [Low (<12) / Medium (13-50) / High (>50)]
• Typical values: [List 3-5 example values from a TOP-5 sample
  query; omit for name, email, phone, address, or ID fields]
• Common use: [Filter / Color encoding / Row grouping / etc.]

• Purpose: [What user decision this enables]

• Allowable values: [Not available via MCP; confirm with the owner]
• Default: [Not available via MCP; confirm with the owner]
• What it controls: [Not available via MCP; confirm with the owner]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

```
